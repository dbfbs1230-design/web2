# 최종 점검·디버깅·최적화 — 수정23

## 수정한 사항

1. 캐릭터 전체 재생을 빠르게 다시 시작하거나 개별 파트로 전환할 때 이전 파트 간 대기 예약이 남을 가능성을 수정했습니다. 선택/탭 전환 시 해당 시계의 프레임·타이머·효과를 함께 초기화합니다. 화면 밖 재생이 늦게 되살아나거나 재시작한 여정에 이전 진행이 끼어드는 것을 방지합니다.
2. Place 추가 거점 마커에 지도 마커 식별 클래스를 적용했습니다. 마커를 누르는 입력이 동시에 지도 드래그로 처리되지 않도록 기존 지도 입력 필터를 재사용합니다. 마커의 좌표·크기·모양은 유지합니다.
3. 글자 배치에서 기존 위치나 주변 빈자리를 찾으면 즉시 반환하도록 최적화했습니다. 필요할 때만 화면 전체 후보를 만들고 정렬합니다. 인물 문구가 없으면 거점/도구의 사각형을 측정하지 않고, 다른 탭·표지·숨겨진 페이지에서는 인물 배치 프레임을 예약하지 않습니다.
4. 오래된 표지·미구현 상태를 설명하던 README를 현재 구현 기준으로 갱신했습니다.

## 보존한 내용

사건/인물/장소 원고, 모든 경로 데이터와 격자, 공통 사건 ID, 사모의 최신 전쟁 경로, 높새바람 탑 부근 행적, 상고토 영역, 875ms 경로 시간과 1초 파트 간격을 유지했습니다. 이미지·폰트 최적화와 해상도별 지도 선택도 기존 방식을 유지합니다. 새 외부 의존성은 없습니다.

## 실제 검사 결과

종합 브라우저 시나리오 244개 검사를 통과했습니다.

- 초기 입장과 기본 거점7, 14개 Place의 제목·마커·선택 해제, 모든 HTML 참조 파일 응답.
- 추가 거점의 pointerdown이 지도 드래그를 활성화하지 않는지 확인.
- 공통 사건 도착 후 표시, 3인 집결 병합과 선택 해제 색 복원, 가사상태·비형 구출 병합, 무룬강 개인 행동 분리.
- 390×844, 820×1180, 1440×900, 844×390에서 가로 넘침·문구 겹침·확대/전체보기 좌표 검사.
- 캐릭터00 빠른 재시작, 개별 파트 전환 후 이전 대기 예약의 간섭 없음.
- 구출대·쇼자인테쉬크톨·전쟁 전체 완주, 일시정지 상태의 지도 DOM 유지, 이전/다음과 재개, 탭 이탈 취소.
- 사모의 남진4개 구간, 표지 복귀·재입장.
- 유휴 상태에서 추적한 RAF/타이머 예약0. document.hidden 변경과 visibilitychange로 숨김 상태를 모사한 검사에서도 예약0. 실제 운영체제 절전 측정이나 브라우저 프로세스 메모리 측정은 아닙니다.

추가로 6인 전체 경로를 동시에 완주했습니다. 완료 후 임시 마스크0·중복 DOM ID0·좌표 오류0이며, 선택 해제 후 6인 경로 레이어0·예약0을 확인했습니다. 모든 시나리오에서 수집된 콘솔 오류는 0개였습니다.

JS 전체 문법, 기존 공통 시계, 사건 ID/장소/역할 검사도 통과했습니다. 최적화 전후 100개 배치 입력의 결과가 일치하며, 원고/경로/속도 파일이 바뀌지 않았음을 비교했습니다.

## 다시 검사하는 방법

Node.js가 있다면 다음을 실행합니다.

```sh
node tools/check-playback.cjs
node tools/check-occurrences.cjs
```

브라우저 종합 검사는 Live Server 등으로 사이트를 연 상태에서 tools/final-browser-check.html을 열고 실행 버튼을 누릅니다. 6인 전체 재생은 tools/character-browser-check.html로 검사합니다. 두 페이지는 개발용이며 실제 홈페이지에서 불러오지 않습니다. 검사 중 창을 보이는 상태로 유지해야 합니다. 검사기는 자체 iframe의 예약 작업을 계측하고 검사 완료 후 원래 함수를 복원합니다.

## 검증 한계

현재 검사는 로컬 Chromium 계열 브라우저와 화면 크기 변경 기반입니다. 실제 스마트폰·태블릿의 터치 하드웨어, Safari, 느린 네트워크, GitHub Pages 배포 주소의 검증은 별도입니다. 원작 사실·정밀 동선의 추가 검증은 이번 코드 최종 점검 범위에 포함하지 않았습니다.
